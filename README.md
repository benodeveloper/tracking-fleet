# Tracking Fleet: Real-Time Vehicle Tracking API

## API

### Vehicles

| Method | Endpoint | Description |
| --- | --- | --- |
| `POST` | `/api/v1/vehicles` | Create a vehicle |
| `GET` | `/api/v1/vehicles` | List vehicles (paged) |
| `GET` | `/api/v1/vehicles/{id}` | Get a vehicle |
| `PUT` | `/api/v1/vehicles/{id}` | Update a vehicle |
| `PATCH` | `/api/v1/vehicles/{id}/status` | Change vehicle status |
| `PATCH` | `/api/v1/vehicles/{id}/mileage` | Update vehicle mileage |
| `DELETE` | `/api/v1/vehicles/{id}` | Delete a vehicle and its location history |

### Locations

| Method | Endpoint | Description |
| --- | --- | --- |
| `POST` | `/api/v1/vehicles/{id}/locations` | Record a location |
| `GET` | `/api/v1/vehicles/{id}/locations/latest` | Get the latest location |
| `GET` | `/api/v1/vehicles/{id}/locations` | Get location history (paged, optional `from`/`to`) |
| `GET` | `/api/v1/vehicles/live` | Get the latest location of every vehicle |

## Swagger UI / OpenAPI

Interactive API documentation is available through Swagger UI, generated by
[springdoc-openapi](https://springdoc.org/).

### Start the application

```bash
SPRING_PROFILES_ACTIVE=local ./gradlew bootRun
```

If you are not using the `local` profile, export `DB_USERNAME` and `DB_PASSWORD` first (see
[Configuration](#configuration)).

### Open the documentation

| Resource | URL |
| --- | --- |
| Swagger UI | <http://localhost:8081/swagger-ui.html> |
| OpenAPI JSON | <http://localhost:8081/v3/api-docs> |
| OpenAPI YAML | <http://localhost:8081/v3/api-docs.yaml> |

Replace `8081` with your `SERVER_PORT` value when using a different port.

### Try an endpoint

1. Open Swagger UI and expand the **Vehicles** or **Locations** tag.
2. Select an operation, for example `POST /api/v1/vehicles`.
3. Click **Try it out**.
4. Replace the example request body with your data and click **Execute**.
5. Inspect the response body, response code, and the generated `curl` command.

To record a location, create a vehicle first and copy its `id` from the response. Use that value as
the `vehicleId` in `POST /api/v1/vehicles/{vehicleId}/locations`. History queries accept optional
ISO-8601 `from` and `to` query parameters, for example
`2026-01-01T00:00:00Z`.

The API currently has no authentication, so no authorization step is required in Swagger UI.

The documentation configuration lives in
`src/main/java/com/tracking/fleet/shared/api/config/OpenApiConfig.java` and
`src/main/resources/application.yaml`.

## Configuration

Database credentials are **not** stored in the repository. The application reads them from
environment variables:

| Variable | Description | Default |
| --- | --- | --- |
| `DB_URL` | PostgreSQL JDBC URL | `jdbc:postgresql://localhost:5432/tracking_db` |
| `DB_USERNAME` | Database username | required |
| `DB_PASSWORD` | Database password | required |
| `SERVER_PORT` | HTTP port | `8081` |

Example:

```bash
export DB_USERNAME=your_username
export DB_PASSWORD=your_password
./gradlew bootRun
```

### Local profile

For local development, copy the example file and fill in your credentials:

```bash
cp config/application-local.example.yaml config/application-local.yaml
```

`config/application-local.yaml` is ignored by Git. Run the application with the `local` profile:

```bash
SPRING_PROFILES_ACTIVE=local ./gradlew bootRun
```
